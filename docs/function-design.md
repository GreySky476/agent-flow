# 2026-05-19-工作流模块设计
## 1. 工作流概述
- 工作流（Workflow）是由多个步骤（Step）组成的有向无环图（DAG），每个步骤代表一个操作单元，如调用 LLM、执行代码、查询数据库等。
- 工作流定义了步骤之间的依赖关系，确保按照正确的顺序执行。
- 工作流实例化后会被执行引擎调度，执行过程中会记录每个步骤的输入、输出和状态。
- 工作流可复用，可配置在其它工作流下调用，实现复杂的业务逻辑编排。
- 工作流设计的核心目标是提供一个灵活、可扩展的框架，支持各种类型的步骤和复杂的依赖关系，同时保证执行的可靠性和可监控性。
## 2. 主要组件
工作流目前分为两种类型组件
- 基础组件
  - 开始组件
  - 结束组件
  - LLM 组件
    - 支持选择不同的 LLM 模型，若不选择，则路由默认模型
    - 参数：
      - 模型选择（可选）
      - system prompt（可选）
  - RAG 组件
    - 选择一个或多个知识库进行检索，默认查询
    - 运行机制：提供 rag 能力给 ai，由 ai 决定是否调用 rag 组件以及如何调用
  - Tool 组件
    - 选择一个或多个工具进行调用
    - 运行机制：提供 tool 能力给 ai，由 ai 决定是否调用 tool 组件以及如何调用
- 分支组件
  - 逻辑分支组件
    - 条件分支（if-else）
      - 包含、不包含、正则、等于、不等于、大于、小于、大于等于、小于等于等条件类型
- 待扩展
  - 从代码层面留出接口，未来可增加更多组件类型，如循环组件、并行组件等
## 3. 工作流定义
- 工作流定义由用户通过 UI 创建，包含工作流名称、描述、输入参数定义、步骤定义等信息
- 步骤定义包含步骤名称、类型、输入参数定义、下游步骤等信息
- 工作流定义会被保存到数据库中，供执行引擎加载和实例化使用
- 工作流定义支持版本管理，用户可以创建工作流定义的多个版本，执行时可以指定使用哪个版本
## 4.工作流界面与交互
- 工作流列表界面：展示所有工作流定义，支持搜索、过滤、查看详情、新建等操作
- 工作流编辑、新建界面：展示工作流定义的详细信息，包括组件列表和可自定义编辑的组件参数
- 工作流执行界面：点击执行后展示一个窗口，有输入、输出以及错误信息展示等选项，方便观察工作流执行的过程和结果
- 工作流设计好后可以发布，可以在工作流列表编辑是否公开该工作流，公开后在【工作流聊天】功能下可见
## 5.可测试入口
- 在功能栏加一个【工作流聊天】功能。设计一个工作流交互界面，在工作流列表点击执行后进入该界面，该页面是一个聊天页面，与微信等软件页面相似。
- 左侧为当前设计好已发布的工作流图，右侧为聊天窗口，右侧输入文本与之交互，并且输出结果。
